# Testing

How CEDI Control is tested and which test covers each requirement of the spec (§34) and each rule of the plan. Test names are quoted in their original Spanish wording, so they can be found with a text search.

## Levels

| Level       | Tool                                          | What it covers                                                                                       | Command                    |
| ----------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------- |
| Unit        | Vitest                                        | Shared schemas, services with mocked dependencies, web logic                                         | `npm test`                 |
| Integration | Vitest + real PostgreSQL (`DATABASE_URL_TEST`) | Full API over HTTP, database constraints, concurrency                                                | `npm run test:integration` |
| E2E         | Playwright (Chromium) + axe                   | Gatehouse flow in a real browser, roles, session, WCAG 2.1 AA accessibility, tablet and keyboard     | `npm run test:e2e`         |
| Coverage    | `@vitest/coverage-v8`                         | Unit + integration (API), with minimum thresholds                                                    | `npm run test:coverage`    |

Integration and E2E tests need `npm run db:up`. They use the `cedi_test` database, never the development one, and leave it empty when they finish. The E2E tests start their own API (:3100) and web (:5174), so they do not clash with `npm run dev`.

**Coverage** (Phase 9): API 97 % of lines / 86 % of branches; `shared` 95 % / 100 %; web logic 91 % / 90 %. Measured again on 2026-10-27: API 98 % / 88 %; web logic 92 % / 90 %. The `.tsx` components are covered by the E2E tests. Thresholds: API ≥ 90 % / 80 %, `shared` ≥ 90 % / 90 %, web ≥ 85 % / 85 %.
